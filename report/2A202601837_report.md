## 1. Executive Summary

This report documents the design, implementation, and evaluation of the **Defense-in-Depth AI Security Gateway** for the Enterprise IT Help Desk system. The system protects operational tools, sensitive internal data, and customer infrastructure against prompt injection, data leakage, RAG poisoning, tool abuse, and unauthorized cross-tenant operations.

---

## 2. Security Architecture & Core Guardrail Modules

### 2.1 Input Protection (`input_guardrails.py`)
- **Unicode Normalization (NFKC)**: Strips zero-width characters (`\u200b`, `\u200c`, `\u200d`, `\ufeff`, `\u2060`) to defeat hidden prompt injection bypasses.
- **Dual-Layer Injection Detector**: Combines Vietnamese & English regex pattern matching with external **Lakera Guard API** (`https://api.lakera.ai/v2/guard`).
- **Cloudflare Turnstile Verification**: Anti-bot validation for incoming requests.
- **IT Support Topic Filter**: Restricts queries to IT support topics while permitting defensive cybersecurity reports (e.g., phishing reporting).

### 2.2 Sensitive Data & Output Protection (`output_guardrails.py`)
- **Microsoft Presidio PII Anonymizer**: Automatically scans and anonymizes personal data (Phone numbers, Email, CMND/CCCD, Credit Card numbers, IP addresses).
- **Secret & Credential Redaction**: Regex-based redaction of passwords, API keys, Bearer/JWT tokens, private keys, and database connection URIs (e.g., `mysql://user:pass@host/db` -> `[REDACTED_DATABASE_URI]`).
- **OpenAI Moderation API & Gemini Safety Judge**: External safety evaluation via OpenAI Moderation endpoint and Google GenAI Gemini.
- **RAG Groundedness Evaluation**: Verifies that generated troubleshooting guidance is strictly backed by retrieved KB documents.

### 2.3 Access Control & Multi-Tenant Isolation (`access_guardrails.py`)
- **Tenant Isolation**: Strictly partitions ticket and KB document access by `company_unit`. Cross-company operations (e.g., VinUni user accessing VinFast tickets) are automatically denied and audited.
- **Role-Based Access Control (RBAC)**: Maps tool permissions to roles (`employee`, `technician`/`helpdesk`, `manager`, `admin`).

### 2.4 Attachment & Threat Security (`attachment_guardrails.py`)
- **Attachment Pipeline**: File extension/size validation -> text extraction -> prompt injection scan -> PII redaction -> **VirusTotal v3 API** & **Google Safe Browsing API** URL threat analysis.

### 2.5 Policy-Driven Tool Execution (`tool_guardrails.py`)
- Enforces the core security rule: **"The LLM may propose, but only the Guardrail decides."**
- High-risk operations (e.g., `reset_password`, `restart_database`, `change_firewall`, `production_change`) automatically trigger Human-in-the-Loop (HITL) approval.

### 2.6 Decision Routing, SLA & Security Incidents
- **Zero Auto-Close Policy (`auto_close_guardrail.py`)**: Forbids automated closure for P1/P2 production incidents, VIP tickets, security incidents, or ungrounded resolutions.
- **Security Incident Escalation (`security_incident_guardrail.py`)**: Automatically detects phishing/compromise requests and routes them directly to the SOC with high priority.
- **Risk-Aware Router (`hitl.py`)**: Maps Confidence (High/Medium/Low) x Risk (Low/Medium/High) x Context to determine `AUTO`, `REVIEW`, or `HITL`.

## 4. Responsible AI & Operational Observability

- **Audit Logging (`audit_log.py`)**: Logs every security decision with timestamp, tenant, user ID, policy ID, confidence, risk score, and detailed rationale to `outputs/audit_log.json`.
- **Metrics & Threshold Monitoring (`monitoring.py`)**: Tracks real-time block rates and safety judge failure rates, triggering automatic alerts when threshold limits are breached (`BLOCK_RATE_THRESHOLD=0.5`, `JUDGE_FAIL_RATE_THRESHOLD=0.3`).
- **Egress Gateway (`pipeline.py`)**: Enforces HTTPS allowlists and inspects outbound HTTP payloads for inadvertent secret leakage.
